# Dyadic Agents

[Skills](https://github.com/HiLleywyn/dyadic-skills) · [Agents](https://github.com/HiLleywyn/dyadic-agents) · [Plugins](https://github.com/HiLleywyn/dyadic-plugins)

Agent definitions for [Dyadic](https://dyadic.app/developers/): the primary assistant Iris and the delegated specialists ("subagents"). An agent package holds identity, instructions, declared tools and delegation boundaries. Reusable procedures live in [dyadic-skills](https://github.com/HiLleywyn/dyadic-skills); built-in tool switches are described in [dyadic-plugins](https://github.com/HiLleywyn/dyadic-plugins).

An agent definition is not a running process and cannot widen server-side policy. The Dyadic runtime resolves installed skills and tools under the user's account and current permissions.

## Layout

| Path | Contents |
| --- | --- |
| [agents/](agents/README.md) | Iris, the primary agent (source snapshot only; not exported) |

| `<agent>/import.json` | Explicit portable tool suggestions used by the export |
| [catalog.json](catalog.json) | Machine-readable inventory, regenerated by `tools/catalog.py index` |
| [provenance.json](provenance.json) | Dyadic source revision, source path and SHA-256 for every official snapshot file |
| [compatibility/](compatibility/) | `native-tools.json` (known tool IDs) and `skill-dependencies.json` (locked skill hashes) |
| `tools/catalog.py` | Shared index/check/build tool (identical in the agents, plugins and skills repos) |
| `tools/verify_dyadic.py` | Optional check of built archives against a Dyadic checkout's package inspector |
| `tests/`, `.lley/run.py` | Offline unittest suite and the JUnit-verifying runner used by CI |

## Validate and build

Requires Python 3.11+ and PyYAML.

```sh
python -m pip install PyYAML
python tools/catalog.py check   # metadata, links, provenance hashes, dependency locks
python .lley/run.py             # test suite; writes reports/catalog.xml and fails on any skip
python tools/catalog.py build   # dist/<agent-id>.zip, dist/checksums.json, dist/collection.zip
```

`check` rejects a changed official snapshot without a matching `provenance.json` update, broken relative links in any `README.md`, unknown tool IDs and unresolved skill dependencies. Builds are deterministic (sorted entries, fixed timestamps) and never execute bundled resources.

With a [dyadic-skills](https://github.com/HiLleywyn/dyadic-skills) checkout alongside this one, `python tools/catalog.py build --skills ../dyadic-skills --output dist-with-skills` produces dependency-bundled archives. It fails if a bundled skill no longer matches the hash locked in `compatibility/skill-dependencies.json`; review the skill change and refresh the lock rather than bypassing it.

`tools/verify_dyadic.py --source ../Dyadic --skills ../dyadic-skills/dist --agents dist --bundled-agents dist-with-skills --plugins ../dyadic-plugins --report reports/dyadic-compatibility.json` parses the built bytes with Dyadic's own `packages.inspect` and compares plugin descriptors with Dyadic's surfaced tool switches. It needs Dyadic's Python dependencies importable, and makes no account installation or provider call.

## Using the packages in Dyadic

Upload an individual `dist/<agent-id>.zip` through Dyadic's reviewed package import. `dist/collection.zip` is only a download container; extract it and import one package at a time. Imported agents are strict delegated copies with memory off; they do not replace built-in defaults and Iris is deliberately not exported. See [COMPATIBILITY.md](COMPATIBILITY.md) for the import routes and limits.

## Maintenance

1. Official snapshots (Iris and the specialists marked "Official snapshot") are owned by Dyadic's `catalog/agents/` and `agents/iris/`. Change them there first, then copy the complete files from a committed Dyadic revision and update `provenance.json` with the new revision and hashes. There is no automated sync tool for this repository.
2. Repository-authored roles are edited here directly. Keep IDs and the `agents/` versus `subagents/` split stable.
3. Review `import.json` tool suggestions and, when a linked skill changes, refresh its entry in `compatibility/skill-dependencies.json`.
4. Run `python tools/catalog.py index`, then `check`, `.lley/run.py` and `build`. Indexing refreshes `catalog.json`; it does not bless snapshot hashes.
5. `tools/catalog.py`, `tests/` and `.lley/run.py` are shared with dyadic-plugins and dyadic-skills. Apply changes to all three and run each repository's checks.

## CI

[.github/workflows/ci.yml](.github/workflows/ci.yml) runs `python .lley/run.py` and `python tools/catalog.py build` on every push and pull request. `.lley/pipeline.json` declares the same stage for the lley.cat mirror's runner. Neither deploys anything or changes Dyadic's Store; publishing here does not update the product catalog or installed account copies.
